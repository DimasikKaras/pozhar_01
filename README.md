# ПожНадзор.pro — Информационная система ГПН МЧС России

Комплексная автоматизированная система для органов Государственного пожарного надзора МЧС России.

## 🚀 Быстрый запуск в Docker:

```bash
docker compose up --build -d
```

После запуска сервисы доступны:
- 🌐 **Фронтенд:** http://localhost:3000
- ⚙️ **API Swagger Документация:** http://localhost:8000/docs
- 🗄️ **PostgreSQL:** порт 5432 (пользователь: postgres, пароль: postgres, БД: pozhnadzor)

---

## 🛡️ Резервное копирование (Backups)

Система поддерживает два взаимодополняющих способа резервного копирования:
1. **Через веб-панель Администратора (в 1 клик с выбором ПК / Docker)**.
2. **На уровне контейнеров Docker (автоматический сервис `db-backup` по расписанию Cron)**.

---

### 🖥️ 1. Резервное копирование через панель Администратора

В интерфейсе системы перейдите в раздел **«Резервное копирование»** (доступно под ролью Администратора):

#### Создание бэкапа:
- 💻 **На компьютер админа:** мгновенно скачивает файл `pozhnadzor_backup_...json` прямо в браузер на ваш жесткий диск.
- 🐳 **В Docker на сервере:** бэкенд сохраняет резервную копию в изолированное хранилище сервера `/backups` с возможностью указать комментарий/метку (например, `перед_обновлением`).

#### Восстановление (Restore):
- 💻 **Файл с компьютера:** загрузите ранее сохраненный `.json` файл с диска ПК (с предпросмотром количества объектов, проверок и оборудования, и выбором режима: полная замена или слияние).
- 🐳 **Файл из Docker:** интерактивный список всех снимков, хранящихся на сервере в Docker: выбор нужного бэкапа в 1 клик, просмотр размера/даты, кнопка мгновенного восстановления и возможность скачать файл на ПК при необходимости.

---

### 🐳 2. Автоматический сервис `db-backup` в Docker

В `docker-compose.yml` встроен выделенный сервис **`db-backup`** на базе `postgres:16-alpine`:
- Автоматически по Cron создает сжатые дампы PostgreSQL (`.sql.gz`) каждый день в 03:00 ночи.
- Хранит дампы в каталоге сервера `./backups`.
- Автоматически удаляет копии старше 7 дней.

Быстрые команды на сервере:
- **Создать бэкап сейчас:** `./scripts/backup-now.sh`
- **Восстановить из последнего дампа:** `./scripts/restore-db.sh`
- **Посмотреть файлы:** `ls -lh ./backups/`

## 🚀 Как применить изменения на сервере

Когда вы отправите обновленный код в свой GitHub-репозиторий (`git push`), выполните на сервере следующие шаги:

```bash
# 1. Перейдите в каталог проекта на сервере
cd /opt/pozhnadzor  # или ваш путь к проекту

# 2. Получите свежие изменения из GitHub
git pull origin main

# 3. Создайте папку для бэкапов на хосте и задайте права (если ее еще нет)
mkdir -p backups
chmod +x scripts/*.sh docker-backup/*.sh

# 4. Пересоберите и перезапустите контейнеры в фоне
docker compose up -d --build

# 5. Проверьте статус запущенных контейнеров
docker compose ps

# 6. (Опционально) Посмотреть логи бэкенда или сервиса бэкапов
docker compose logs -f backend
docker compose logs -f db-backup
```
